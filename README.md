# srelog

Один бинарник вместо трёх bash-скриптов из `sre-notes` — и без шага «открой файл в редакторе».

Находка попадает в журнал одной командой: `srelog add` берёт текст со stdin, дописывает его в нужную секцию сегодняшней записи, при необходимости заводит саму запись и тут же пересобирает `INDEX.md` с `BACKLOG.md`.

```bash
srelog add <<'EOF'
### Бридж не ходит на prod-cp-01

Весь разбор шёл локальным kubectl.
EOF
```

## Установка

```bash
cargo install --path .
```

## Первый запуск

Журнал заводится одной командой: `init` создаёт `oncall/` с шаблоном записи, README и пустыми `INDEX.md` с `BACKLOG.md`.

```bash
srelog init ~/sre-notes
export SRELOG_ROOT=~/sre-notes
```

Повторный `init` ничего не перезаписывает: свой `TEMPLATE.md` останется своим. Каталог года не создаётся заранее — его заводит первая запись. Git тут не обязателен, но если каталог всё же репозиторий, имя дежурного возьмётся из его `user.name`.

`init` предупредит, если `SRELOG_ROOT` указывает на другой журнал или если выше по дереву уже есть `oncall/`. Предупреждения идут в stderr и не меняют код возврата.

## Как добавлять

Секция задаётся первым позиционным аргументом, по умолчанию «Находки». Годится часть имени или латинский синоним: `находки`/`findings`, `итог`/`summary`, `контекст`/`context`, `артефакты`/`artifacts`, `бэклог`/`backlog`, `вопросы`/`questions`.

```bash
echo 'Разбор INC-42 шёл целиком локальным kubectl.' | srelog add итог
srelog add бэклог <<< '| tooling | L0-тул quota_check | Бридж не ходит на prod-cp-01 |'
srelog add находки < ~/notes/raw.md
srelog add артефакты -f a.md -f b.md
```

Строка таблицы приклеивается к таблице бэклога без пустой строки, всё остальное дописывается в конец секции через пустую строку. Записи за сегодня может ещё не быть — она заведётся сама.

`-t/--title` заворачивает добавляемое в подзаголовок, это удобно для находки без готовой разметки:

```bash
srelog add -t 'Логи h3vm живут около часа' <<'EOF'
Приди я на сутки позже, доказательств бы не осталось.
EOF
```

## Заголовки во входящем файле

Файл с черновиком обычно живёт своей жизнью: у него свой `# H1`, свои `## H2` и YAML-шапка. Всё это нельзя вставлять в запись как есть — `##` разорвёт её на новые секции.

Фронтматтер отрезается всегда. С заголовками `--headings` решает, что делать:

| Режим | Что происходит |
|-------|----------------|
| `shift` (по умолчанию) | сдвигает всю лестницу вглубь, чтобы верхний заголовок встал на уровень ниже секции: `#` → `###`, `##` → `####`. Вложенность сохраняется, глубже шестого уровня не уходит и вверх никогда не поднимает |
| `bold` | `## Что делать` → `**Что делать**` |
| `strip` | строки заголовков выбрасываются, остаётся один текст |

Заголовки внутри блоков кода не трогаются, так что `# комментарий` в bash-примере останется комментарием.

## Остальные команды

```bash
srelog init [ПУТЬ]    завести журнал (по умолчанию в текущем каталоге)
srelog shift [ДАТА]   создать пустую запись из шаблона
srelog index          пересобрать oncall/INDEX.md
srelog backlog        пересобрать oncall/BACKLOG.md
srelog sync           пересобрать оба файла
srelog sections       показать секции сегодняшней записи
srelog template       напечатать встроенный шаблон
```

`add` и `shift` пересобирают генерируемые файлы сами; `--no-sync` это отключает, если добавляешь пачкой.

Корень заметок ищется в три приёма: флаг `--root <path>`, переменная `SRELOG_ROOT`, поиск `oncall/` вверх от текущего каталога. Переменная проверяется раньше поиска, так что выставленный в профиле `SRELOG_ROOT` уводит команды в свой журнал из любого каталога. Имя дежурного — из `ONCALL_ENGINEER`, иначе из `git config user.name` в репозитории заметок, иначе `TBD`.

## Шаблон

Шаблон сведён к скелету: фронтматтер, заголовок и шесть пустых секций. Подсказки из него убраны — они дублировали `oncall/README.md`, а после появления `add` мешались, потому что оставались в файле рядом с реальным текстом. Пустая строка-заглушка в таблице бэклога тоже не нужна: строки добавляются командой.

Берётся `oncall/TEMPLATE.md` из репозитория заметок, а если его нет — встроенный. Перейти на новый:

```bash
srelog template > oncall/TEMPLATE.md
```

Формат записей при этом не меняется: `srelog` читает и старый шаблон, и старые записи.

## Замена Makefile в sre-notes

```makefile
add: ## дописать stdin в секцию (S=находки)
	@srelog add $(S)

shift: ## создать запись (DATE=YYYY-MM-DD)
	@srelog shift $(DATE)

sync: ## пересобрать INDEX.md и BACKLOG.md
	@srelog sync
```

После этого `scripts/oncall-*.sh` можно удалить.

## Разработка

`make` без цели печатает список целей.

```bash
make check                    # fmt-check + clippy -D warnings + тесты
make test
make run ARGS="sections --root ~/sre-notes"
make install
```

`make parity` копирует репозиторий заметок во временный каталог, прогоняет по копии старые bash-скрипты и новый бинарник и сравнивает `INDEX.md` с `BACKLOG.md`, игнорируя строку с именем генератора. Оригинал не трогается.

```bash
make parity NOTES=~/sre-notes
```

Цель работает, пока в репозитории заметок лежат `scripts/oncall-*.sh`; после их удаления сверять станет не с чем, и `make parity` честно об этом скажет.

Зависимость одна — `chrono`, только ради локальной даты. Всё остальное на std. Разбор markdown в `src/md.rs` и покрыт тестами: сдвиг заголовков, блоки кода, фронтматтер, вставка в секцию, склейка строк таблицы.
