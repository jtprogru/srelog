# srelog

Один бинарник вместо трёх bash-скриптов из `sre-notes` — и без шага «открой файл в редакторе».

Находка попадает в журнал одной командой: `srelog add` берёт текст со stdin, дописывает его в нужную секцию сегодняшней записи, при необходимости заводит саму запись и тут же пересобирает `INDEX.md` с `BACKLOG.md`.

```bash
srelog add <<'EOF'
### Бридж не ходит на prod-cp-01

Весь разбор шёл локальным kubectl.
EOF
```

## Установка

```bash
cargo install --path .
```

## Первый запуск

Журнал заводится одной командой: `init` создаёт `oncall/` с шаблоном записи, README и пустыми `INDEX.md` с `BACKLOG.md`, а рядом с `oncall/` кладёт `srelog.toml` со списком направлений.

```console
$ srelog init ~/sre-notes
создано: /Users/me/sre-notes/oncall
создано: /Users/me/sre-notes/oncall/TEMPLATE.md
создано: /Users/me/sre-notes/oncall/README.md
создано: /Users/me/sre-notes/srelog.toml
создано: /Users/me/sre-notes/oncall/INDEX.md
создано: /Users/me/sre-notes/oncall/BACKLOG.md

srelog ищет журнал через SRELOG_ROOT; без неё он найдётся только изнутри этого каталога.
Закрепи путь в профиле оболочки:

  echo 'export SRELOG_ROOT="/Users/me/sre-notes"' >> ~/.zshrc

и в текущей сессии:

  export SRELOG_ROOT="/Users/me/sre-notes"
```

Команду можно скопировать как есть: профиль выбирается по `$SHELL` (`~/.zshrc`, `~/.bash_profile` или `~/.bashrc`, `~/.config/fish/config.fish` с `set -gx`, иначе `~/.profile`), путь берётся в кавычки. Если переменная уже указывает сюда, `init` просто это подтвердит; если на другой журнал — скажет, куда сейчас уходят команды, и даст строку для замены.

`init` безопасен и на уже заполненном журнале: записи и `TEMPLATE.md` не трогаются, добавляются разве что `README.md` и `srelog.toml`, если их не было. `INDEX.md` и `BACKLOG.md` собираются из записей заново — если содержимое разошлось, они попадут в вывод отдельной строкой `пересобрано:`, и ручные правки в них не переживут этого (как не переживают и обычный `add`). Когда на диске ничего не изменилось, `init` так и скажет.

Повторный `init` ничего не перезаписывает: свои `TEMPLATE.md` и `srelog.toml` останутся своими. Каталог года не создаётся заранее — его заводит первая запись. Git тут не обязателен, но если каталог всё же репозиторий, имя дежурного возьмётся из его `user.name`.

Про вложенность `init` тоже предупредит: если выше по дереву уже есть `oncall/`, заводить второй журнал внутри первого почти всегда опечатка. Всё это идёт в stderr и не меняет код возврата, в stdout остаётся только путь корня.

## Как добавлять

Секция задаётся первым позиционным аргументом, по умолчанию «Находки». Годится часть имени или латинский синоним: `находки`/`findings`, `итог`/`summary`, `контекст`/`context`, `артефакты`/`artifacts`, `бэклог`/`backlog`, `вопросы`/`questions`.

```bash
echo 'Разбор INC-42 шёл целиком локальным kubectl.' | srelog add итог
srelog add бэклог <<< '| tooling | L0-тул quota_check | Бридж не ходит на prod-cp-01 |'
srelog add находки < ~/notes/raw.md
srelog add артефакты -f a.md -f b.md
```

Строка таблицы приклеивается к таблице бэклога без пустой строки, всё остальное дописывается в конец секции через пустую строку. Записи за сегодня может ещё не быть — она заведётся сама.

`-t/--title` заворачивает добавляемое в подзаголовок, это удобно для находки без готовой разметки:

```bash
srelog add -t 'Логи h3vm живут около часа' <<'EOF'
Приди я на сутки позже, доказательств бы не осталось.
EOF
```

## Заголовки во входящем файле

Файл с черновиком обычно живёт своей жизнью: у него свой `# H1`, свои `## H2` и YAML-шапка. Всё это нельзя вставлять в запись как есть — `##` разорвёт её на новые секции.

Фронтматтер отрезается всегда. С заголовками `--headings` решает, что делать:

| Режим | Что происходит |
|-------|----------------|
| `shift` (по умолчанию) | сдвигает всю лестницу вглубь, чтобы верхний заголовок встал на уровень ниже секции: `#` → `###`, `##` → `####`. Вложенность сохраняется, глубже шестого уровня не уходит и вверх никогда не поднимает |
| `bold` | `## Что делать` → `**Что делать**` |
| `strip` | строки заголовков выбрасываются, остаётся один текст |

Заголовки внутри блоков кода не трогаются, так что `# комментарий` в bash-примере останется комментарием.

## Статус кандидата

У таблицы «Кандидаты в бэклог» есть четвёртая колонка — `Статус`. Пока ячейка пустая, кандидат открыт и стоит в основной таблице `BACKLOG.md`. Когда задачу завели в трекер, сделали или сняли, в ячейку пишется ссылка на тикет или пара слов. При следующей пересборке строка уезжает в раздел «Заведено и снято» в конце `BACKLOG.md`, со статусом и ссылкой на дежурство, а в самой записи остаётся как была.

```markdown
| Направление | Что завести | Основание | Статус |
|-------------|-------------|-----------|--------|
| tooling | Тул `quota_check(project_id)` | Бридж не видит квоты | |
| infra | Обновить драйвер хранилища | Тихая порча данных | [PROJ-123](https://tracker.example/PROJ-123) |
| infra | Обновить драйвер хранилища | Рецидив | повтор 2026-09-03 |
```

Колонка необязательная. Трёхколоночные таблицы в старых записях собираются как раньше, строки на три и на четыре ячейки можно смешивать даже в одной таблице, так что `srelog add бэклог` с тремя ячейками тоже годится. Ячейки правее статуса отбрасываются. Пока статуса нет ни у одного кандидата, раздела «Заведено и снято» в `BACKLOG.md` нет вовсе.

`srelog backlog` сообщает в stderr, сколько строк легло в каждый раздел: `открыто 12, заведено и снято 3`. В stdout, как и раньше, только путь к файлу.

Встроенный шаблон уже с четвёртой колонкой, но существующий `oncall/TEMPLATE.md` `init` не перезаписывает: в журнале, заведённом раньше, колонку в шаблон стоит добавить руками.

## Направления

Первая колонка таблицы кандидатов — направление: `infra`, `tooling`, `process` и так далее. `BACKLOG.md` группирует строки по нему, так что задача, записанная в одной смене как `storage`, а в другой как `infra`, разъедется по разным концам таблицы. Чтобы новое направление не появлялось молча, список допустимых лежит в `srelog.toml` в корне журнала, рядом с `oncall/`:

```toml
directions = ["access", "dev", "docs", "infra", "observability", "process", "tooling"]
```

Команды, которые пересобирают `BACKLOG.md`, то есть `add`, `sync`, `backlog` и `init`, сверяют со списком каждую строку и про незнакомое направление пишут в stderr путь и номер строки:

```console
$ srelog sync
/Users/me/sre-notes/oncall/INDEX.md
srelog: /Users/me/sre-notes/oncall/2026/2026-09-03.md:14: направления `storage` нет в srelog.toml
/Users/me/sre-notes/oncall/BACKLOG.md
```

Запись при этом не отклоняется и код возврата не меняется: находка важнее классификации, направление можно поправить потом. В обеих таблицах `BACKLOG.md` направления идут в порядке списка, внутри направления строки сортируются как раньше, незнакомые уезжают в конец.

`srelog.toml` кладёт `init` и дальше его не трогает, список правится руками. Нет файла или ключа `directions` — нет и проверок, а сортировка прежняя, по строке целиком. Поэтому журнал, заведённый раньше, собирается как собирался, пока в нём не появится `srelog.toml`. Появиться он может и от повторного `init`: тогда список из шаблона сразу включит проверку, а `BACKLOG.md` пересоберётся в новом порядке. Сломанный файл писать тоже не мешает: `srelog` скажет, в какой строке ошибка, и соберёт `BACKLOG.md` без проверок.

Из TOML `srelog` понимает ровно то, что нужно для списка: массив строк в двойных или одинарных кавычках, переносы внутри массива и комментарии через `#`. Всё, что ниже первой таблицы `[...]`, не читается.

## Остальные команды

```bash
srelog init [ПУТЬ]    завести журнал (по умолчанию в текущем каталоге)
srelog shift [ДАТА]   создать пустую запись из шаблона
srelog index          пересобрать oncall/INDEX.md
srelog backlog        пересобрать oncall/BACKLOG.md
srelog sync           пересобрать оба файла
srelog sections       показать секции сегодняшней записи
srelog template       напечатать встроенный шаблон
```

`add` и `shift` пересобирают генерируемые файлы сами; `--no-sync` это отключает, если добавляешь пачкой.

Корень заметок ищется в три приёма: флаг `--root <path>`, переменная `SRELOG_ROOT`, поиск `oncall/` вверх от текущего каталога. Переменная проверяется раньше поиска, так что выставленный в профиле `SRELOG_ROOT` уводит команды в свой журнал из любого каталога. Имя дежурного — из `ONCALL_ENGINEER`, иначе из `git config user.name` в репозитории заметок, иначе `TBD`.

## Шаблон

Шаблон сведён к скелету: фронтматтер, заголовок и шесть пустых секций. Подсказки из него убраны — они дублировали `oncall/README.md`, а после появления `add` мешались, потому что оставались в файле рядом с реальным текстом. Пустая строка-заглушка в таблице бэклога тоже не нужна: строки добавляются командой.

Берётся `oncall/TEMPLATE.md` из репозитория заметок, а если его нет — встроенный. Перейти на новый:

```bash
srelog template > oncall/TEMPLATE.md
```

Формат записей при этом не меняется: `srelog` читает и старый шаблон, и старые записи.

## Замена Makefile в sre-notes

```makefile
add: ## дописать stdin в секцию (S=находки)
	@srelog add $(S)

shift: ## создать запись (DATE=YYYY-MM-DD)
	@srelog shift $(DATE)

sync: ## пересобрать INDEX.md и BACKLOG.md
	@srelog sync
```

После этого `scripts/oncall-*.sh` можно удалить.

## Разработка

`make` без цели печатает список целей.

```bash
make check                    # fmt-check + clippy -D warnings + тесты
make test
make run ARGS="sections --root ~/sre-notes"
make install
```

`make parity` копирует репозиторий заметок во временный каталог, прогоняет по копии старые bash-скрипты и новый бинарник и сравнивает `INDEX.md` с `BACKLOG.md`, игнорируя строку с именем генератора. Оригинал не трогается.

```bash
make parity NOTES=~/sre-notes
```

Цель работает, пока в репозитории заметок лежат `scripts/oncall-*.sh`; после их удаления сверять станет не с чем, и `make parity` честно об этом скажет.

Зависимость одна — `chrono`, только ради локальной даты. Всё остальное на std, включая `srelog.toml`: из TOML `src/config.rs` разбирает ровно список направлений. Разбор markdown в `src/md.rs` и покрыт тестами: сдвиг заголовков, блоки кода, фронтматтер, вставка в секцию, склейка строк таблицы, статус кандидата, направление и номер строки. Команды целиком, со stdout, stderr и кодом возврата, проверяет `tests/cli.rs`.
