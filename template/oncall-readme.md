# Журнал дежурств

Каталог заведён `srelog init`. Дальше всё пишется командами, руками сюда лезть почти не нужно.

## Что где лежит

| Путь | Что это |
|------|---------|
| `<год>/<YYYY-MM-DD>.md` | запись за одно дежурство, единственный файл, который правят руками |
| `TEMPLATE.md` | шаблон новой записи; правь под себя, `srelog` берёт его вместо встроенного |
| `INDEX.md` | сводная таблица дежурств, генерируется |
| `BACKLOG.md` | кандидаты в бэклог из всех записей, генерируется |
| `../srelog.toml` | настройки журнала рядом с `oncall/`: список направлений для таблицы бэклога |

`INDEX.md` и `BACKLOG.md` пересобираются целиком при каждом `add`. Правки в них пропадут — правь запись, из которой строка приехала.

## Как писать

```bash
srelog add <<'EOF'
### Короткий заголовок находки
Что увидел, что проверил, чем кончилось.
EOF

echo 'Одной строкой: чем закончилась смена.' | srelog add итог
srelog add бэклог <<< '| tooling | что завести | основание |'
```

Секция — первым позиционным аргументом, по умолчанию «Находки». `srelog sections` покажет, какие секции есть у сегодняшней записи.

Последняя колонка таблицы бэклога — `Статус`. Пустая ячейка значит, что кандидат открыт. Когда задачу завели в трекер, сделали или сняли, впиши в ячейку ссылку на тикет или пару слов: строка переедет из основной таблицы `BACKLOG.md` в раздел «Заведено и снято». Удалять строку из записи не нужно.

Первая колонка — направление. Допустимые перечислены в `srelog.toml` в корне журнала, и новое направление сначала стоит добавить туда. Незнакомое запись не остановит: `srelog` предупредит с путём и номером строки, а в `BACKLOG.md` поставит такого кандидата в конец таблицы.
